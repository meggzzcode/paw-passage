# PWA: install, service worker, offline

Optional features. The website stays primary: nothing requires installing, and nothing here requests a permission.

## Files

- `public/manifest.webmanifest`: name Paws & Passage, standalone, `start_url` and `scope` `/`, theme `#234D44` (the site's existing theme color), background `#f7f0e1` (`--pp-paper`). Icons 192 and 512 (any) plus 512 maskable.
- `public/icons/*`: generated by `python3 scripts/pwa-icons.py` (Pillow) from the paw geometry in `src/components/shell/Logo.tsx`. Original brand art. Each file is under 60 KB (largest about 27 KB). `apple-touch-icon.png` (180) is also there; the head still links the older `/apple-touch-icon.png`.
- `public/sw.js`, `public/offline.html`.
- `src/lib/pwa.ts`, `src/components/site/Install{Prompt,Card,Guide,Runtime,Illustrations}.tsx`, `src/routes/install.tsx`.
- `netlify.toml`: `/sw.js` is `no-cache` with `Service-Worker-Allowed: /`; manifest has the correct media type.

## Service worker rules

- Precaches only public static assets (fonts, icons, manifest, `offline.html`) in a versioned cache `pp-static-<VERSION>`. Bump `VERSION` in `sw.js` to ship changes; old `pp-static-*` caches are deleted on activate.
- Never touches `/api/*`, non-GET, cross-origin requests; nothing authenticated or premium is ever stored. Pages are not cached: navigations are network-first and only a failed navigation shows `offline.html`, which says plainly that most things need a connection.
- Update path: a new worker waits. The page shows a small "A new version is ready" toast with Refresh (posts `SKIP_WAITING`, reloads once on `controllerchange`). Without the click it takes over after all tabs close. First install is silent. Registration happens after `load`, client-only, and is skipped in the Vite dev server.
- `push`: parses the JSON payload (kind, title, body, url, tag) per the V5 contract, shows title and body only (no extra data on the lock screen), `tag` dedupes. `notificationclick`: re-validates `url` (same origin, exact allow-list match, plan id `pl-` + 8 [a-z0-9]), focuses an existing window and navigates, else opens a window; anything else falls back to `/`.

## Install prompt behavior

`InstallPrompt` is mounted only (a) in the activation/restore success state (`AccessForms.tsx`) and (b) in the free-flow completion panel (`FreeStarter.tsx`). Not shown in standalone mode, and not again for 90 days after "Not now" (`pp.install.dismissedAt` in localStorage, wrapped in try/catch). `InstallCard` is an always-available entry for My Passport/settings (P3 mounts it). "Install" uses the captured `beforeinstallprompt` where Chromium offers it, otherwise links to `/install`. Analytics (`install_guide_viewed`, `install_initiated`, `install_detected`) go through `track()`, guarded by try/catch; they are dropped until P3 adds the names to the allow-list.

## Storage in the installed app (investigation)

- iOS/iPadOS: a Home Screen web app is not part of Safari and has its own usage counter (WebKit, "Full Third-Party Cookie Blocking and More"). Practical consequence, widely reported and not tested here (UNVERIFIED on device): the installed app starts with empty localStorage and cookies, separate from the Safari tab. So progress made in the browser does not appear in the installed app by itself.
- Android Chrome (WebAPK): same origin, same Chrome profile storage, as commonly documented. UNVERIFIED on device; do not depend on it. If Chrome falls back to a plain shortcut it is just a browser tab.
- Mitigation shipped: the install guide has a "Restore access" card (links to `/restore-access`, mentions progress export/import in My Passport). Free intro progress moves via export/import; purchases via the existing restore flow with the emailed code. Purchase codes are never placed in URLs or query strings.

## Verified against sources (read 2026-11-26)

- Apple, "Bookmark favorite webpages in Safari on iPhone": open in Safari, Share (or Page Menu then Share), Add to Home Screen, Add. https://support.apple.com/guide/iphone/iph42ab2f3a7/ios
- WebKit, "Web Push for Web Apps on iOS and iPadOS": Home Screen web apps with a standalone/fullscreen manifest, iOS/iPadOS 16.4, permission request needs a direct user action; third-party browsers may offer Add to Home Screen from 16.4 if entitled. https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/
- WebKit ITP post (separate counter for Home Screen apps). https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/
- web.dev, "Installation": Android Chrome menu says Install or Add to Home Screen (wording varies); desktop Chromium shows an install badge in the address bar and may list Install in the menu. https://web.dev/learn/pwa/installation
