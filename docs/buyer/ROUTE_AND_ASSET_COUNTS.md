# Route and asset counts (recount of 2026-11-24)

Purpose: one place for every headline number a buyer or a listing may quote, with the method, so the numbers can be re-run. Nothing here is a traffic, revenue, ranking or valuation figure.

## Method

- Source: committed code at `HEAD` `56552fc` (parent chain includes `b0f371a`). Uncommitted edits by other workers (citation presentation, guide bodies) are NOT included, so numbers that depend on guide text may move after they land. Re-run the method below after the final commit.
- Build: `git archive HEAD` extracted to a scratch folder, `bun install` (522 packages), `NITRO_PRESET=node-server bunx vite build` (succeeded), then `node .output/server/index.mjs` on a local port. No live site was fetched for these counts.
- Sitemap: `curl /sitemap.xml` from that build, grouped by first path segment. The sitemap is generated by `src/lib/sitemap-entries.ts` (same indexing rules as the pages).
- Crawl: Playwright Chromium visited all sitemap URLs plus every `/stays`, `/guides`, `/gear`, `/destinations`, `/dogs` and `/tools` link found on those pages (109 addresses requested; 3 were legacy gear addresses that 301 to a category page, so 106 distinct rendered pages). All returned HTTP 200 (legacy addresses redirect with 301 first). Google, Amazon and Vrbo hosts were blocked in the browser, so no tracking or affiliate request was made.
- Data counts: a throwaway vitest probe (not committed) over the app's own modules (`allGuides`, `isPublic`, `products`, `visibleStays`, `liveCategories`, `destinations`, `dogTypes`, `managerPolicies`, `affiliateLinks`, `sitemapEntries`).
- Tests: `bunx vitest run` in the scratch build.
- Word counts: whitespace-split words of each published guide's Markdown body (includes `{{pick:}}` card directives and link syntax; excludes FAQs, sources and page chrome).
