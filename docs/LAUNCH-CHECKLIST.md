# Launch checklist

Status as of 2026-11-26 (Q3 review against the current code; the full area-by-area table is `LAUNCH-READINESS.md`). A gate is **Pass** only when it was verified; otherwise **Not done**, **Blocked** (needs an external task) or **Defect**.

## Verdict

Choose one:

- **READY** - every gate below passes.
- **READY AFTER EXTERNAL SETUP** - everything in the code and content passes; only the owner tasks in `COWORK-HANDOFF.md` remain.
- **NOT READY** - at least one gate fails for a reason inside the repository.

**Current verdict: READY AFTER EXTERNAL SETUP, with one in-repository item to close first** (the stale build output and the default `publish` check, see `LAUNCH-READINESS.md`). Nothing is launch-ready until the external items below are done and the real-device and real-checkout items stay NOT verified until a person runs them. Earlier reasons, still the external work:

1. The browser wiring for the premium library and sync exists (`premium-client.ts`, `sync.ts`) and is tested against a fake server only. Re-verify (the browser wiring is now also covered by `launch-commerce.test.ts` at HTTP level) it against the real Function, Blobs and Gumroad on a preview deploy (CW-NET-5, CW-PAY-4) before claiming it works.
2. The Gumroad license integration is unverified (CW-PAY-1) and no seller account, product or checkout link exists (CW-PAY-2, CW-PAY-3).
3. Nothing has run on Netlify: the deploy path, `/api/*` routing, environment isolation and Blobs behavior are unverified (CW-NET-4, CW-NET-5, CW-NET-2).
4. No real-device test has been done (CW-QA-1).
5. No premium library has been imported to any store (CW-BLOB-3), so the paid product cannot be delivered yet.

Items 1 to 5 are external verification or setup. Gift checkout is an optional evaluation, **not a launch blocker**, and is not advertised anywhere on the site.

4. Keep the previous deploy available for rollback until the first week is clean.
