# Editorial scorecard, batch 5 (vacation-rental guides)

Method: Playwright Chromium at 390 and 1280 px against the frozen build at localhost:4174; source bodies read in full. Word counts are rendered article text (source body incl. markup is higher). Phone scroll = document scrollHeight at 390 px. No horizontal page scroll on any page; every table is 544 px wide inside a 350 px scroll box (swipe-to-read on phone). Trust count = rendered affiliate notices + "how sure we are" block + "general information / not advice" lines + "read 2026-11-18 / convenience sample / our judgment / unknown" statements (approximate, regex plus manual).

Rendered citation format (all six): a bare superscript number, `<sup class="cite"><a href=... aria-label="Source 4">4</a></sup>`, no brackets visible. Before-example (reactive): "Airbnb says to contact the host even when a listing allows pets.⁴" and "avoidance 'isn't a permanent solution.'² ³". The markdown source shows `[[4]](url)`. Problem: clusters of 5-6 adjacent numbers ("[[18]] [[21]] [[22]] [[23]] [[24]] [[19]]" in the senior guide) are unreadable on a 390 px screen and the tap targets are tiny.

Cross-cutting (applies to all six): every page is 2,700-3,500 words (16,000-19,500 px on phone, about 25 screens) for questions that need 1,200-1,800. Every page ends with the same stack: "What to buy first" list, "How sure we are", sometimes "What we could not confirm" table, "Next step". Same three products (Kurgo Loft Wander, MidWest iCrate, Soggy Doggy mat) recur across 5 of 6 pages with near-identical copy. Source frontmatter has `research:`/competitor blocks that are internal, not shown, so fine.

- E format: good bones. Jump links, short-answer bullets, bold trigger blocks, blockquote host message (copy-paste is the best element). - F utility/affiliate: utility high (host message, first-day plan). Affiliate is mild but forced: a 26 in gate that "will not stop a dog that can jump it", a crate that "does not block the view", a KONG. Each is hedged out of usefulness. Honest, but a reactive-dog parent wants window film, a white-noise machine or a covered crate, none of which are offered. Commercial fit 5.

## Batch summary
Averages: reactive 6.6, senior 7.4, large-dog 6.8, no-weight-limit 5.4, no-pet-fee 6.4, costs 6.4 (batch mean 6.5). Verdicts: 4 STRUCTURAL EDIT, 2 MERGE (pages 3 and 4 into one hub; page 4 is the removable one).

Top patterns:
1. Length is 40-60% over what the question needs; every page has the same tail stack (buy-first list, "How sure we are", unknowns table, next step), and pages 3-6 repeat the same manager tables and Sliding Rock/Hapey/Twiddy facts.
2. Trust-signalling is excessive: roughly 6-11 reassurance/disclaimer statements per page (affiliate notices, "convenience sample" up to 3x, "read 2026-11-18", "how sure we are", "not advice"), plus 21-46 superscript markers rendered as bare numbers, sometimes six in a row. It reads like a research memo and slows phone reading.
3. Gear sections are generic (same Kurgo bed, iCrate, doormat on four pages) and openly self-undermined ("no page says this changes what a host charges", "does not block the view"); affiliate is honest but forced. The Vrbo search CTA is the one natural commercial link.
4. Each page does have one excellent, specific asset: the copy-paste host message, the six-limit quote table, the photo-request checklist, the definite/refundable split. The fix is cutting around those, not rewriting.
5. Phone: no page overflows, but 2-3 wide tables per page are swipe-only; page length is about 23-25 phone screens.
