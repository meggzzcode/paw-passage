# Google setup: Search Console and Google Analytics (GA4)

Written 2026-11-26. The site was rebuilt from a different business (a dog-friendly stays directory). Search Console and GA4 were set up for the OLD site, so they hold old URLs, old sitemaps and old events. This document says which pages deserve SEO, what to delete from Search Console, and how to update GA4. It is checked by `src/test/google-setup.test.ts`, which fails if a row below stops matching the code.

Rules: no claim here says anything is indexed or will rank. Google UI paths marked UNVERIFIED were not read on a Google help page; the others come from the help pages named in section 5.

## 1. Indexing table

Never add a Disallow for a private page.

### 1.1 Recommendations and open decisions

- OD-G1, `/discover`: the owner asked for it to be noindex. The code indexes the plain URL (and noindexes every `ctx` and `mode` variant). My recommendation is to keep the plain URL indexable: it is the product entry, the sitemap lists it, and it is the destination of every Journal call to action. It is a client-rendered tool with little text, so expect it to rank for little. If the owner prefers noindex, set `noindex: true` in `src/routes/discover.tsx`, remove `/discover` from `staticPaths`, and change the two `/discover` rows in `src/test/google-setup.test.ts`.
- OD-G2, `/previews`: recommendation is noindex. It loads its cards from `/api/previews` in the browser, so the server HTML carries little, and the previews exist to feed the product, not to rank. Today it is indexable but not in the sitemap, which mixes signals. This is the same decision as OD7 in `COWORK-HANDOFF.md`. To apply: `noindex: true` in `src/routes/previews.tsx` and flip the row in the test.
- Collections tabs: `/collections?tab=mine` and `?tab=favorites` have the canonical `/collections` and no noindex. They show only the visitor's own data on their device, so there is nothing private in the server HTML, and Google folds them into the canonical. Optional hardening (owner of `src/routes/collections.index.tsx`): noindex when `tab !== "curated"`.
- Policies stay indexable and are listed; they have priority "none" because nobody should expect them to rank.

### 1.2 Fixes made to the code by this review

- Added `/how-we-write-adventures` and the two free sample printable pages (`/printables/adventure-bucket-list`, `/printables/indoor-discovery-bingo`) to the sitemap (indexable pages that were not listed).

## 3. Google Analytics (GA4)

Measurement ID: see `ga4MeasurementId` in `content/settings.yml`: `G-1J97C8CPC1`.

### 3.1 How it works in the code (read from the repo)

- Loader: `src/routes/__root.tsx` adds an inline snippet to every page: a `gtag` stub, `gtag('config', id)`, and the `googletagmanager.com/gtag/js` script loaded after page load when the browser is idle. The ID comes from settings; an empty ID loads nothing.
- Consent: there is NO consent code. The script loads for every visitor, in every region, with default consent behavior. Nothing is deferred until the visitor agrees, and there is no consent-mode call. `/privacy` says Google Analytics sets cookies (`_ga`), and offers Google's opt-out add-on or blocking scripts. This is OD4.
- Passport events: `src/passport/events.ts`. `track(name, params)` only sends names in the allow-list, only when `window.gtag` exists (so ad blockers send nothing), and sends the event to GA4 as `pp_<name>` (for example `pp_purchase_cta_clicked`). Parameter keys must match `^[a-z0-9_-]{1,40}$`; string values must match the same pattern, so free text is dropped, never sent. `transport_type: beacon` is added.
- Other events: `src/lib/analytics.ts` sends unprefixed `product_click` (params `product_id`, `partner`, `link_url`, `page_path`) and the tool events `tool_start`, `tool_complete`, `tool_copy`, `tool_print`, `packing_trip_edited`, `packing_custom_added`, `packing_item_packed`, `packing_item_need_to_buy`, `packing_recommendation_opened` (params `tool_name`, `tool_label`, `item_count`, `page_path`). These belong to the guides, gear and packing planner, which are kept.
- Campaign fields: `src/lib/campaign.ts` keeps the first `utm_source`, `utm_medium`, `utm_campaign` of a tab session and attaches them only to `pp_purchase_cta_clicked` and `pp_checkout_started`. Per tab session only; not attributed across days or devices.

### 3.3 Parameters allowed (names only)

Every event may carry any key that matches the pattern, but the code only passes these: `where` (a slug such as `home-hero`, `unlock`, `unlock-gift`, `match-panel`, `keepsake-<where>`, or a Journal context key), `source` (a Journal article slug or a suggestion source), `adventure` (an adventure id), `stage` (dog life stage), `kind` (keepsake, milestone, a reminder kind), `reason` (activated or restored), plus `utm_source`, `utm_medium`, `utm_campaign` on the two purchase-funnel events. GA4 adds `transport_type`. Never: dog name, memory text, license code, email, customer id, photo data. A test (`src/test/analytics-events.test.ts`) guards the allow-list.

### 3.6 Cookie consent (OD4): what each choice changes

Today: no consent code, GA4 loads for everyone and sets `_ga` cookies; `/privacy` documents this and says the site works without analytics. Choices:

1. Keep as is (US-first audience). Simplest; most complete data. Visitors from the EU, UK and some other regions may require consent: ask the lawyer in `POLICIES-REVIEW.md` item D2. No consent banner and no consent-mode call.
2. Banner plus Google consent mode: needs a consent banner (new feature, not in the code today), a default-denied `gtag('consent','default', ...)` call before `config`, and an update on accept. With denied analytics storage, GA4 may use cookieless pings and modeled data; the reports then show fewer observed users and, for a low-traffic site, modeling may not activate (UNVERIFIED: not read on a help page). Key-event counts for denied visitors are partial.
3. No banner, cookies off: send `gtag('config', id, { client_storage: 'none' })`-style cookieless measurement or drop analytics for visitors in regulated regions (UNVERIFIED parameter, not read on a help page). Fewer returning-user and session metrics, funnels get less reliable because each page view looks like a new user.
4. Remove GA4 entirely: clear `ga4MeasurementId` in `content/settings.yml`; nothing is loaded and `track()` returns false. No data at all.

Whatever is chosen, update the Cookies section of `/privacy` (D3 in `COWORK-HANDOFF.md`) to say exactly what is set. A test pins that no consent code exists today; whoever implements option 2 or 3 updates that test and the privacy text together.

### 3.7 Attributing purchases (limits)

- Purchases cannot be attributed to pins or Journal articles in GA4 yet. GA4 records a click on the buy button (`pp_purchase_cta_clicked`, `pp_checkout_started`) with the session's first UTM tags, then the visitor leaves for gumroad.com. The sale is not sent back to GA4, the UTM is not carried to Gumroad, and there is no cross-domain link. `pp_purchase_confirmed` fires only when the buyer later activates their code on our site, and only if they come back and analytics runs.
- What Gumroad's own dashboard can show instead: UNVERIFIED (not read on a Gumroad help page). Expect sales counts, revenue and possibly referrer or UTM data per sale, but check the Gumroad analytics and product pages before promising anything; the owner reads this off the Gumroad dashboard directly. Compare weekly purchase-button clicks in GA4 with Gumroad sales as a directional ratio only; the click-to-sale ratio is never a conversion rate proof.
