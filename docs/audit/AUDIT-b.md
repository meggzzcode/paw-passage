# Audit B: six guides (4 destination, 2 gear)

Reviewer stance: skeptical buyer. Labels: [MEASURED] = seen on a page, URL given; [ESTIMATE] = my judgment. No search volume, difficulty, traffic or ranking data exists; none is claimed.

Method note on competitors: I ran live web searches for each main query and record what surfaced [MEASURED, search-result pages only; I did not open each result in full]. Each guide's own `research.competitors` block also lists pages the original author says were read in full; I cite those as "per guide research, not re-verified". Competitor counts are therefore a SERP-composition read, not a full competitor teardown.

## Cross-cutting findings (apply to all six)

1. None of the six uses the 38-manager pet-policy dataset or any docs/data CSV. The site's stated differentiator is absent from every article in this batch. [MEASURED: grep of the six files finds no use; the dataset is only wired to DogAcceptedChecker and dog-accepted.ts].
2. Prose is careful and sourced but repetitive and over-hedged. Recurring tics: "not a guarantee", "confirm with the host", "does not mean", "check the current page", "not a recommendation of any rental". The four destination guides open with a bulleted "short answer" that is mostly warnings. Boutique-publication voice is largely missing; there is almost no scene, opinion, or named favorite.
3. Honesty is a real strength (explicit "no rental inspected", modeled-vs-published drive times, source on nearly every claim). It is also a commercial weakness: the guides tell readers what to ask, but never show a single place to stay.
4. `content/affiliates.yml` is empty and `src/content/stays/verified.ts` is 6 lines with no verified stays [MEASURED]. Destination guides therefore have no booking destination. Both gear guides contain "Some links on this site are affiliate links, marked as sponsored" while no affiliate link is approved; a reader sees a disclosure with nothing to disclose. Harmless but slightly odd.
5. All six: publishedOn and lastReviewed both 2026-11-16, i.e. nothing has yet been through a maintenance cycle.

## 1. dog-friendly-cabins-fenced-yards-georgia

**Current title:** Dog-Friendly Cabins With Fenced Yards in Georgia (seoTitle: "Georgia Cabin Fenced Yards: What to Check")

## Destination guides: can they ever rank without verified stays? How well do they set up a future stays/affiliate section?

**Could they rank without verified stays?** [ESTIMATE throughout]
- For the head terms (cabins/rentals/getaways), probably not on page one in the near term. SERP composition I saw is OTAs (Airbnb, Vrbo, Expedia), property managers (Vacasa, AvantStay), state tourism boards and large editorial brands (Sunset, CBS, Consumer-type authority) [MEASURED composition]. A new site with an informational method guide and no places is a weak match for a shopping query.
- They can plausibly rank for long-tail informational queries where the SERP is thin: "does a gated deck count as a fenced yard", "can dogs go on the Tallulah Gorge suspension bridge", "Joshua Tree dogs on trails", "are dogs allowed at Carmel Beach off leash". Those are separate, narrower questions; the guides bury them as sections. Standalone short answer pages, or restructured guides, would suit these better.
- Ranking also depends on external links and brand signals the site does not yet have.

**Do they set up a future stays/affiliate section?**
- Partly. Positive: each has a stays-adjacent section (host message, shortlist, pet-cost tool) that can host a "Verified stays" block; the stays data layer exists (`src/content/stays/verified.ts`, filters on confirmed values only) and the Georgia/California destination hubs link these guides [MEASURED].
- Negative: none of the four has a defined slot, data hook, or phrase pattern that references stays; none names a base town with a lodging type so that a verified listing could be dropped in; they say outright "No rental has been inspected" and "This guide does not recommend individual rentals", which a future stays block would contradict, requiring edits. - The affiliate path is cleaner for the two gear guides (pick cards bound to productId) than for destination guides (no affiliate for stays approved; the doc docs/AFFILIATE-PROGRAMS.md is the only reference).
- Recommendation: add a reserved, data-driven "Stays we have verified near here" component per guide, tied to the stays dataset, and rewrite the "not a recommendation" language to "stays appear here only after verification".
