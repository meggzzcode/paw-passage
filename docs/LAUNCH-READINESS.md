# Launch readiness (Q3 review, 2026-11-26)

Reviewed against the current code. "Verified" means a local automated test or a static read, never a live service. No real charge, account, device or deploy was used. Nothing here claims a real-device or real-checkout result.

## Verdict: READY AFTER EXTERNAL SETUP (one in-repository item first)

The commercial code paths behave correctly against fakes. Launch still needs owner and Cowork work that cannot be done locally. One item is inside the repository and must be settled before the owner setup is worth starting: the **deploy path** (blocker 1).

### Blockers

1. **Deploy path unproven, possibly wrong (in repository).** `npm run build` writes `.output/` with a Nitro `cloudflare-module` preset (`.output/nitro.json`, `vite.config.ts` comment), while `netlify.toml` says `publish = "dist"` and serves `netlify/functions/api.ts`. HTML pages are server-rendered, so a Netlify deploy may not serve them from this output. No Netlify deploy has ever run (CW-NET-4/5). Fix applied: `netlify.toml` now sets `NITRO_PRESET = "netlify"`; a local build with it writes the static site to `dist/` and the server-rendered pages to `.netlify/functions-internal`, and the leak check passes on both. Lead or Cowork must still prove one preview deploy serves pages and `/api/*` before anything else.
2. **Gumroad contract UNVERIFIED (CW-PAY-1).** Endpoint, `product_id` / `license_key` / `increment_uses_count`, and the response fields `success`, `purchase.id`, `refunded`, `chargebacked`, `disputed`, `dispute_won`, `license_disabled` are from memory. If any is wrong, activation fails closed (503 or 403): nobody is wrongly granted, but nobody can buy. No seller account or product exists (CW-PAY-2/3).
3. **No premium library imported** to any store (CW-BLOB-3). Until then the paid product, the showcase previews and the public counts have no data (previews fall back to an honest empty answer).
4. **No real-device QA** (CW-QA-1): iPhone Safari, Android Chrome, install, share, photo picker, notifications.
5. **Pages CMS adventure form is out of date** (`CONTENT`/CMS gate 20): new adventures cannot be created correctly in the CMS. Disable CMS adventure editing or update the form.

Not blockers: GA4 delivery (CW-ANA-1), gift checkout, notifications (off by default, kill switch).

## Environment variables (names only)

Netlify Functions scope: `SESSION_SECRET` (32+ chars), `PP_DATA_KEY` (set once, never change), `GUMROAD_PRODUCT_ID`. Preview and dev only: `PP_ALLOW_TEST_PROVIDER`. Build scope (public): `VITE_CHECKOUT_URL`. Optional notifications: `NOTIFICATIONS_ENABLED`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (secret), `VAPID_SUBJECT`. Owner terminal only: `NETLIFY_AUTH_TOKEN`, `SITE_ID`. There is no `PP_ENV`; the store is chosen from the deploy context. The notification variables are in `NOTIFICATIONS.md`, not yet in the `OPERATIONS.md` table.

## What a nontechnical buyer needs

A GitHub account (repository transfer), a Netlify account (site transfer), the domain registrar login, a Gumroad account or a plan to re-list the product, Pages CMS sign-in with their own GitHub account, the private premium JSON file and a dated backup (handed over outside the repository), the three secrets re-created at closing, and `OPERATIONS.md` plus `FLIP-HANDOFF.md`. Everyday editing is Pages CMS for guides, collections and settings. Premium changes need a person comfortable running two terminal scripts, so a buyer without that skill needs a short paid handover session. The Pages CMS adventure form must be fixed or hidden first.

## Decisions needing owner approval

1. Accept up to 24 hours between a refund or chargeback and loss of access (no webhook), or pay for a webhook design later.
2. A license key is not limited to one device or person (restore works from any device; `increment_uses_count=false`). Accept key sharing risk, or set a use limit once the Gumroad contract is read.
3. Which host stays: the current Nitro build targets another platform. Confirm Netlify and the build target (blocker 1), or choose the host the build supports.
4. Disable CMS adventure editing until the form is rebuilt.
5. Keep notifications off at launch and revisit after the first week of real credit usage.
6. Analytics: confirm GA4 stays opt-out friendly and slug-only, and that no dog names are ever allowed as slugs.
7. Slogan: the tagline is "A lifetime of little adventures."; "Collect adventures, not just things" stays out of the hero and H1 with its guard test, unless the owner says otherwise.
